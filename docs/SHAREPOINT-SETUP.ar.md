# إعداد SharePoint وMicrosoft Entra لمنصة مداد كلية الشريعة والأنظمة

الرابط: **https://gradtheses-taif.netlify.app**

هذا دليل مسار Entra/Graph الاختياري. **المسار المختار حاليًا هو [الدخول عبر SharePoint القائم](NATIVE-SHAREPOINT.ar.md)**، ولا يحتاج تنفيذ هذه الخطوات أو إعداد طلب إداري. لا يعني وجود هذا الدليل أن الاتصال أو حماية الملفات قد اختُبرا.

## 1. ما نحتاجه من صاحب المشروع

1. رابط موقع SharePoint المؤسسي الذي ستعتمده الكلية، أو تكليف تقنية المعلومات بإنشائه.
2. مسؤول يستطيع تسجيل تطبيق في Entra، ومنح موافقة المسؤول وصلاحيات القائمة، وتعيين دور القراء.
3. قرار بمن يسمح له بالقراءة: جميع منسوبي الجامعة أم مجموعة محددة. يجب استبعاد الضيوف من المجموعة إذا كانت السياسة للمنسوبين فقط.
4. عينة من 5–10 سجلات ورسائل معتمدة للنشر والقراءة، والتصنيف الفعلي للأقسام والبرامج. يمكن تزويدنا بروابطها بعد ضبط وصولها؛ لا تنشرها في GitHub.
5. تأكيد مسؤول SharePoint لتوفر وسيلة منع التنزيل والترخيص اللازم، ونجاح اختبار قارئ عادي.

لا نحتاج كلمة مرور حسابك. تُدخل الأسرار مباشرة في لوحة Netlify بواسطة مخوّل؛ لا تُرسل في المحادثة.

## 2. بنية التخزين

- **موقع الإدارة:** الأصول، المسودات، الملاحظات، وسجل المراجعة؛ مقصور على المحررين والمعتمدين.
- **قائمة PublicCatalogue:** داخل موقع الإدارة أو موقع فهرسة مستقل. تضم بيانات النشر المعتمدة فقط. ليست قائمة SharePoint مجهولة الوصول؛ الخدمة الخلفية تنشر حقولًا محددة منها.
- **موقع القراءة:** مكتبة ApprovedTheses لنسخ PDF المعتمدة، مع صلاحيات مجموعة القراء وسياسة منع التنزيل. يفضّل فصل الموقع لأن السياسة تطبق على مستوى الموقع.
- مالكان مؤسسيان على الأقل، وسياسة استمرارية واحتفاظ تعتمدها الجامعة. لا يعتمد المستودع على OneDrive شخصي.

يظل السجل الإداري مصدر الحقيقة، وتُحدّث قائمة PublicCatalogue بعد اعتماد النشر. يمكن بدء ذلك بإدارة يدوية مضبوطة ثم أتمتته في مرحلة لاحقة. لا توجد أتمتة موافقات أو نسخ ملفات منفذة في هذه النسخة.

## 3. قائمة PublicCatalogue وأسماء الأعمدة

**أنشئ الأعمدة باسمها الإنجليزي أولًا لضمان الاسم الداخلي**، ثم يمكنك تغيير عنوان العرض للعربية. الحقل Title موجود افتراضيًا. الحقول النصية plain text، وليست HTML. يحدد YearCalendar تقويم السنة صراحة؛ المصدر الأولي هجري.

| الاسم الداخلي     | النوع                                | القيم/الغرض                                                      |
| ----------------- | ------------------------------------ | ---------------------------------------------------------------- |
| Title             | نص سطر واحد                          | عنوان العمل، مطلوب                                               |
| ThesisId          | نص سطر واحد، فريد ومفهرس             | معرّف ثابت مثل `thesis-0001`؛ حروف إنجليزية وأرقام و`-` و`_`     |
| AuthorName        | نص سطر واحد                          | اسم الباحث، مطلوب                                                |
| SupervisorName    | نص سطر واحد                          | المشرف أو المشرفون                                               |
| Department        | نص سطر واحد                          | اسم القسم الفعلي، مطلوب                                          |
| Degree            | اختيار واحد                          | `ماجستير`، `دكتوراه`                                             |
| WorkType          | اختيار واحد                          | `رسالة علمية`، `بحث تكميلي`، `غير محدد`                          |
| Year              | رقم بلا كسور                         | 1300–1600 هجريًا أو 1900–2200 ميلاديًا، بحسب YearCalendar        |
| YearCalendar      | اختيار أو نص                         | `hijri` أو `gregorian`؛ لا يُحوّل 1447 إلى سنة ميلادية           |
| CoSupervisorName  | نص                                   | مشرف مشارك اختياري                                               |
| Specialization    | نص                                   | التخصص كما ورد في المصدر                                         |
| AcademicStatus    | اختيار واحد                          | `مسجل`، `قيد الإعداد`، `مكتمل`، `غير محدد`                       |
| AbstractText      | نص متعدد الأسطر عادي                 | المستخلص المعتمد للنشر العام                                     |
| KeywordsText      | نص متعدد الأسطر عادي                 | كلمات تفصلها `؛` أو `;`                                          |
| PageCount         | رقم بلا كسور                         | اختياري                                                          |
| AccessLevel       | اختيار واحد                          | `metadata` بيانات فقط، `university` قراءة جامعية، `embargo` مؤجل |
| EmbargoUntil      | تاريخ                                | اختياري، لا يؤدي إلى فتح تلقائي                                  |
| PublicationStatus | اختيار واحد، مفهرس                   | `Draft` أو `Published`؛ القيمة الافتراضية Draft                  |
| ReadingUrl        | نص متعدد الأسطر عادي أو ارتباط تشعبي | رابط القارئ المعتمد داخل مضيف الجامعة؛ لا يظهر في بيانات الجمهور |

لا تضع الأرقام الجامعية أو الملاحظات السرية في هذه القائمة. لا تحوّل `PublicationStatus` إلى Published إلا بعد اعتماد جميع البيانات العامة.

مثال بيانات في Graph (للتوضيح فقط):

```json
{
  "Title": "عنوان رسالة معتمدة",
  "ThesisId": "thesis-0001",
  "AuthorName": "اسم الباحث",
  "SupervisorName": "اسم المشرف",
  "Department": "الفقه",
  "Degree": "ماجستير",
  "WorkType": "رسالة علمية",
  "Year": 2026,
  "AcademicStatus": "مكتمل",
  "AbstractText": "المستخلص المعتمد",
  "KeywordsText": "الفقه؛المعاملات",
  "PageCount": 250,
  "AccessLevel": "university",
  "PublicationStatus": "Published",
  "ReadingUrl": "https://YOUR-TENANT.sharepoint.com/sites/GradThesesReading/REPLACE-WITH-VERIFIED-VIEWER-LINK"
}
```

القيم غير الصحيحة أو السجلات غير المنشورة تُستبعد. تكرار ThesisId بين السجلات المنشورة يعطل الفهرس احترازيًا حتى تصحيح التعارض.

## 4. تطبيق Entra

1. أنشئ App registration باسم GradTheses من نوع **Single tenant** في مستأجر الجامعة.
2. Authentication > Add a platform > **Web**. التطبيق يستخدم خادمًا سريًا، وليس SPA.
3. أضف عنوان العودة حرفيًا: `https://gradtheses-taif.netlify.app/auth/callback`.
4. للتطوير فقط يمكن إضافة `http://localhost:3000/auth/callback` مع APP_URL مطابق. لا تضف نطاقات معاينة عشوائية.
5. لا تفعّل implicit grant؛ التدفق المنفذ Authorization Code + PKCE وstate وnonce والتحقق من توقيع ID token.
6. أنشئ Client secret بمدة مناسبة وسياسة تجديد، وخزّن **القيمة** في Netlify دون نشرها أو إرسالها في المحادثة. يدعم الإصدار الأول سرًا سريًا للخادم؛ يمكن نقل الاعتماد إلى شهادات/هوية موحدة مستقبلًا.
7. App roles > Create app role: القيمة `Theses.Reader`، المسموح **Users/Groups**. عيّنه إلى مجموعة القراء الجامعيين المسموحين، أو للمستخدمين مباشرة إذا لم يسمح الترخيص بتعيين المجموعات.
8. Enterprise applications > التطبيق > Properties > **Assignment required = Yes**. راجع عضوية المجموعة واستبعاد الضيوف وفق السياسة.
9. امنح المجموعة نفسها صلاحية الوصول المناسبة إلى مكتبة القراءة في SharePoint. دور Entra وحده لا يمنح صلاحية الملفات.

تتحقق المنصة من معرّف مستأجر الجامعة ومعرّف المستخدم والدور، ولا تعتمد على نهاية البريد. الجلسة مشفرة HttpOnly وSameSite=Lax ومدتها لا تتجاوز ساعة. لا تحفظ access/refresh tokens في المتصفح.

## 5. صلاحية خدمة الفهرس في Graph

للتطبيق نفسه، أضف Microsoft Graph **Application permission**:

`Lists.SelectedOperations.Selected`

ثم يمنح المسؤول Admin consent ويمنح التطبيق دور `read` على قائمة PublicCatalogue **فقط**. الموافقة على الصلاحية وحدها لا تكفي؛ يلزم منح مورد القائمة صراحة. لا تمنحه Files.Read.All أو Sites.Read.All أو صلاحية الوصول إلى مكتبة الرسائل.

ينفذ مسؤول مخول، باستخدام أدواته الإدارية، طلب المنح التالي. صلاحيات إصدار المنح تبقى للتطبيق/الحساب الإداري ولا تضاف إلى تطبيق التشغيل:

```http
POST https://graph.microsoft.com/v1.0/sites/{siteId}/lists/{listId}/permissions
Content-Type: application/json

{
  "roles": ["read"],
  "grantedToV2": {
    "application": {
      "id": "APPLICATION-CLIENT-ID",
      "displayName": "GradTheses"
    }
  }
}
```

استخرج Site ID وList ID بواسطة Graph Explorer أو أداة الإدارة المعتمدة. معرّف Site قد يتكون من اسم المضيف ومعرّفي GUID مفصولة بفواصل. معرّف التطبيق هو Application (client) ID، وليس Object ID.

[نموذج صلاحيات الموارد المحددة](https://learn.microsoft.com/en-us/graph/permissions-selected-overview) · [منح صلاحية على قائمة](https://learn.microsoft.com/en-us/graph/api/list-post-permissions?view=graph-rest-1.0)

## 6. حماية موقع القراءة

1. تأكد من توفر ترخيص ومتطلبات SharePoint Advanced Management، ومن صلاحية المسؤول.
2. عطّل الروابط المجهولة للموقع، واضبط مجموعة القراء وفق السياسة المعتمدة.
3. يفعّل المسؤول سياسة منع التنزيل على **موقع القراءة فقط**، بعد مراجعة أثرها على إجراءات الكلية. مثال إداري:

```powershell
Set-SPOSite -Identity https://YOUR-TENANT.sharepoint.com/sites/GradThesesReading -BlockDownloadPolicy $true
```

4. إن استخدمت روابط Block download على مستوى الملف كحل بديل، تحقق من صلاحيات المستخدم الأخرى؛ رابط مقيد لا يلغي صلاحية أوسع موجودة بالفعل.
5. ضع في ReadingUrl رابط العرض المحمي الذي اختُبر بالفعل. لا تضع Graph downloadUrl أو preview URL مؤقتًا أو رابط تحميل مباشر. المضيف المقبول واحد بصيغة `tenant.sharepoint.com` والمسارات `/sites/` أو `/:b:/` فقط.
6. لا تستثنِ مجموعة القراء من الحماية. راجع الاستثناءات للملاك والأدوار الإدارية.

تطبيقات app-only مستثناة من سياسة منع التنزيل بحسب مايكروسوفت؛ لهذا يقرأ تطبيقنا قائمة البيانات فقط ولا يجلب الملف الأصلي ولا يمرره عبر Netlify.

[سياسة منع التنزيل](https://learn.microsoft.com/en-us/sharepoint/block-download-from-sites) · [متطلبات الترخيص](https://learn.microsoft.com/en-us/sharepoint/sharepoint-advanced-management-prerequisites) · [روابط منع التنزيل](https://support.microsoft.com/en-us/onedrive/block-downloads-for-view-only-files-in-sharepoint-and-onedrive)

## 7. متغيرات Netlify

Project configuration > Environment variables. اختر النطاق **Builds + Functions** إذا كانت الخطة تسمح بتحديد النطاقات؛ في خطة Free يكون الخيار **All scopes**. اختر السياق **Production** للأسرار، وضعها كقيم حساسة. لا تمكّنها للمعاينات غير الموثوقة. أعد النشر بعد التغيير.

| المتغير                    | القيمة                                                                          |
| -------------------------- | ------------------------------------------------------------------------------- |
| APP_URL                    | `https://gradtheses-taif.netlify.app`                                           |
| CATALOG_SOURCE             | `sharepoint` عند جاهزية الفهرس                                                  |
| ENTRA_TENANT_ID            | Directory (tenant) ID                                                           |
| ENTRA_CLIENT_ID            | Application (client) ID                                                         |
| ENTRA_CLIENT_SECRET        | القيمة السرية، تُدخل مباشرة في Netlify                                          |
| SESSION_SECRET             | سر عشوائي مستقل 64 حرفًا على الأقل؛ يولد محليًا باستخدام `openssl rand -hex 32` |
| ENTRA_READER_ROLE          | `Theses.Reader`                                                                 |
| SHAREPOINT_SITE_ID         | معرّف الموقع الذي يحتوي قائمة النشر                                             |
| SHAREPOINT_CATALOG_LIST_ID | معرّف PublicCatalogue                                                           |
| SHAREPOINT_READING_HOST    | المضيف فقط، مثل `university.sharepoint.com`                                     |
| READING_ENABLED            | `false` أولًا، ثم `true` بعد اختبار الحماية                                     |

المعاينات والفروع الأخرى مضبوطة افتراضيًا على demo والقراءة مغلقة. لا تضع ملفات PDF أو أسرار في GitHub أو مجلد public.

## 8. اختبار القبول قبل الإتاحة

- دون دخول: يستطيع الزائر البحث وقراءة المستخلص، ولا يحصل على رابط الملف من HTML أو `/api/catalog` أو `/api/read/...`.
- حساب خارج الجامعة أو حساب بلا دور القراءة: لا يصل إلى القارئ.
- حساب Reader عادي: يسجل الدخول وتفتح النسخة المعتمدة. تعاد المصادقة في SharePoint إن لزم.
- الرابط المباشر للملف يخضع لشرط الدخول الجامعي ومنع التنزيل والطباعة والمزامنة.
- اختبر PDF عربيًا طويلًا على الجوال وEdge وChrome؛ لا تعتمد على حساب المالك.
- المسودات والنصوص المؤجلة وغير المكتملة لا تفتح. لا تتحول الإتاحة تلقائيًا بانقضاء التاريخ.
- سحب PublicationStatus أو تغيير AccessLevel يمنع فتح الرابط من المنصة في الطلب التالي. سحب وصول SharePoint مطلوب لإلغاء رابط معروف مسبقًا.
- تعطّل Graph ينتج رسالة عدم توفر، دون ظهور عينة مكان البيانات الحقيقية.
- إذا ظهر فهرس فارغ رغم وجود السجلات، تحقق من أسماء الأعمدة الداخلية والقيم الإلزامية وPublicationStatus.

الاختبار الحقيقي للدخول الجامعي ومنع التنزيل متعذر قبل توفير هذا الإعداد. لا تفعّل READING_ENABLED على أساس نجاح اختبارات الواجهة وحدها.
